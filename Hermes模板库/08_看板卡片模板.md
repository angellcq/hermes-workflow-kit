## 一、看板卡片数据结构（设计参考）

```json
{
  "task_id": "【T-001】",
  "title": "【任务标题，动词+对象+结果】",
  "type": "【feature / bugfix / refactor / docs / infra / test】",
  "priority": "【P0 / P1 / P2 / P3】",
  "status": "【todo / in_progress / in_review / blocked / done】",
  "assignee": "【Agent 名称】",
  "created_at": "【ISO8601，如 2026-09-04T10:00:00+08:00】",
  "started_at": "【ISO8601 / null】",
  "due_at": "【ISO8601】",
  "progress": 【0-100】,
  "dependencies": ["【前置任务 ID】"],
  "source": "【DD#章节 ← HLD#组件 ← PRD#US-nn】",
  "files_scope": ["【允许修改的文件路径】"],
  "blocking_issues": ["【阻塞描述，无则空数组】"],
  "context_links": {
    "task_card": "【任务卡文件路径】",
    "prd": "【PRD 文件路径】",
    "hld": "【HLD 文件路径】",
    "dd": "【DD 文件路径】"
  },
  "history": [
    {
      "timestamp": "【ISO8601】",
      "from": "【旧状态】",
      "to": "【新状态】",
      "note": "【变更说明】"
    }
  ]
}
```

## 二、状态流转规则

| 从 | 到 | 触发条件 |
|----|-----|----------|
| todo | in_progress | Agent 确认接收并开始执行 |
| in_progress | in_review | 执行者提交验证（附证据） |
| in_progress | blocked | 遇到无法自行解决的阻塞 |
| blocked | in_progress | 阻塞解除 |
| in_review | done | 模板 07 验证全部通过 |
| in_review | in_progress | 验证未通过，退回修改（闭环上限 2 轮） |

> 仅允许上表流转；跳级流转（如 in_progress 直接 done）视为违规。

```

━━━━━━━━━━━━━━
总数:【N】 ｜ 完成:【N】 ｜ 进行中:【N】 ｜ 阻塞:【N】
今日新增:【列表】
今日完成:【列表（各附交付报告链接）】
阻塞待解:【列表 + 阻塞原因 + 已阻塞时长】
明日重点:【列表】
━━━━━━━━━━━━━━
```
