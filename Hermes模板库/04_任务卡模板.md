# 任务卡模板（合并版）
> **模板编号**: 04 ｜ **环节**: 任务拆解（S4） + 任务派发 ｜ **填写人**: Hermes
> **用法**: 每个任务一张卡，命名 `任务卡_任务ID_短标题.md`；派发时复制第四节"派发通知"发送给执行 Agent
> **拆解规则**: 单卡预估 ≤ 4 小时（超过必须拆分）｜唯一完成标准｜依赖显式声明｜无验收标准/依赖/files_scope 的任务卡不得派发
---
# 任务卡:【PROJECT-NNN】

## 一、基本信息

| 字段 | 内容 |
|------|------|
| 任务 ID | 【T-NNN，全局唯一，拆分子任务用 -a/-b 后缀】 |
| 标题 | 【动词+对象+结果，如"实现用户登录 API 并通过单元测试"】 |
| 类型 | 【feature / bugfix / refactor / docs / infra / test】 |
| 优先级 | 【P0 / P1 / P2 / P3】 |
| 预估工时 | 【X 小时，≤4】 |
| 指派人 | 【Agent 角色 / Claude Code 实例】 |
| 依赖任务 | 【前置任务 ID 列表，无则写"无"】 |
| 来源需求 | 【DD#章节 ← HLD#组件 ← PRD#US-nn，禁止仅写文件名】 |
| 文件边界 (files_scope) | 【本任务允许修改的文件/目录列表；并行任务不得重叠】 |
| 截止时间 | 【YYYY-MM-DD HH:mm】 |
| 当前状态 | 【TODO / IN_PROGRESS / IN_REVIEW / DONE / BLOCKED】 |

## 二、任务描述

【2-5 句话说清楚要做什么、为什么做；引用 DD 章节原文，禁止复述改写。执行者读完这节应能独立开工。】

## 三、完成标准（Definition of Done）

> 💡 每条必须可客观验证（命令可跑、指标可量、文件可见），禁止"基本完成""差不多"类表述

- [ ] 【可验证条件 1，如"登录接口返回 200 且含 token 字段"】
- [ ] 【可验证条件 2，如"单元测试覆盖率 ≥ 80%"】
- [ ] 【可验证条件 3，如"DD 文档第 4 节已同步更新"】

## 四、派发通知（复制本节发送给执行 Agent）

```
📨 任务派发通知
━━━━━━━━━━━━━━
Task:    【T-NNN】
标题:    【任务标题】
指派:    【Agent 名称】
优先级:  【P0-P3】
截止:    【截止时间】
依赖:    【已完成的依赖项 / 无】
来源:    【DD#章节 ← HLD#组件 ← PRD#US-nn】
上下文:
  - 设计文档: 【文件路径 + 章节】
  - 代码位置: 【文件/目录路径】
  - 文件边界: 【仅允许修改以下文件，越界即违规】
  - 特别注意: 【关键约束、项目红线、禁止事项】
完成标准:
  - [ ] 【标准 1】
  - [ ] 【标准 2】
汇报要求: 仅允许三态汇报——完成(附证据)/阻塞(附原因)/偏差(附影响)
回复确认: 收到后请确认接收并预估开始时间
━━━━━━━━━━━━━━
```

## 五、执行上下文

- 代码位置:【相关文件/目录路径】
- 参考实现:【可参考的已有代码或历史任务】
- 特别注意:【关键约束、禁止事项，如"不得修改公共接口签名"】
- 工具建议:【如"用 Claude Code Print 模式，--allowedTools Read,Edit,Write,Bash --max-turns 40"】

## 六、进度记录

> 💡 执行者每次状态变更时追加一行；Hermes 检查点核对时以此为准

| 时间 | 进度 | 状态变更 | 说明 |
|------|------|----------|------|
| 【时间】 | 【%】 | 【IN_PROGRESS】 | 【说明】 |

## 七、验收记录

> 💡 由 Hermes 在验证环节填写，关联交付验证报告（模板 07）

| 验收项 | 结果 | 说明 |
|--------|------|------|
| 完成标准逐条核对 | ✅/❌ | 【逐条结果】 |
| 7 项验证清单 | ✅/❌ | 【详见交付报告链接】 |
| 追踪矩阵回填 | ✅/❌ | 【PRD#US-nn 行已更新】 |
| 最终结论 | 【通过 / 退回修改】 | 【日期 + 验证人】 |

## 附：任务拆解检查表（Hermes 拆任务时自查）

- [ ] 每个任务有且仅有一个明确的完成标准？
- [ ] 单任务预估 ≤ 4 小时？（超过则继续拆）
- [ ] 所有依赖关系已显式声明，无循环依赖？
- [ ] 每个任务标注了优先级和指派人？
- [ ] 每张卡的 files_scope 已声明，并行任务之间无文件重叠？
- [ ] 来源需求用编号串联（DD←HLD←PRD），不是只写文件名？
- [ ] 标题是"动词+对象+结果"格式？
