# 版本记录模板（version.md · 项目级修改追溯）

> **模板编号**: 10 ｜ **环节**: 全生命周期 ｜ **填写人**: 所有 Agent + 工程师本人
> **用法**: 项目根目录维护 `version.md`（或模块级），每次文件被修改时记录修改内容、版本号、修改人
> **硬规则**: 修改任何代码文件后 24 小时内必须追加一行；版本号统一用语义化版本（SemVer）；每次发版前必须有完整 release 条目
> **跨语言适用**: 任何语言/任何规模的项目都适用，作为最低成本的修改追溯机制

## 1. 全局版本号规则

采用 **语义化版本（SemVer）**：`v<MAJOR>.<MINOR>.<PATCH>`

| 变更类型 | 版本位 | 示例 |
|---------|-------|------|
| 不兼容的 API 修改 | MAJOR | v1.x.x → v2.0.0 |
| 向下兼容的功能性新增 | MINOR | v1.2.x → v1.3.0 |
| 向下兼容的问题修正 | PATCH | v1.2.3 → v1.2.4 |

预发布/构建元数据：`v1.0.0-alpha.1` / `v1.0.0-rc.2+build.123`

## 6. Agent 自动化钩子（融合版新增）

> Hermes / Claude Code 等 Agent 修改文件后，自动调用 `version.md append` 写入以下格式：

```bash
# 伪代码：Agent 修改文件后自动追加
version_md_append \
  --file "path/to/file.ext" \
  --version "vX.Y.Z" \
  --agent "Hermes/backend-developer" \
  --summary "一句话变更说明"
```

**Agent 填写纪律**：
- 摘要必须一句话讲清"为什么改"而非"改了什么"（diff 由 git 负责）
- 涉及数据库/API/配置/依赖变更时，必须同时填写 §4 对应小节
- 修改后 24 小时内必须同步到 version.md（这是审计要求，不是建议）
