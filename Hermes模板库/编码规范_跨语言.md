# 第一部分：通用原则（任何语言/任何规模）

## 一、核心原则：不可变性

**始终创建新对象，绝不修改现有对象。**

```
// ❌ 错误：原处修改
modify(original, field, value) → 改变了 original

// ✅ 正确：返回新副本
update(original, field, value) → 返回新对象，original 不变
```

**理由**：
- 不可变数据防止隐藏副作用，简化调试
- 支持安全并发（无需锁）
- 便于回滚与版本控制
- 测试更容易（输入输出一一对应）

**语言特例**：
- 强类型编译型语言：默认不可变（Go: 值类型 / Rust: 所有权）
- 动态语言：用 dataclass / Pydantic / record + `frozen=True` 实现
- 函数式语言：天然支持

## 二、文件组织

| 原则 | 说明 |
|------|------|
| **多小文件 > 少大文件** | 高内聚、低耦合 |
| **典型大小** | 200-400 行 |
| **上限** | 800 行（单文件最大行数） |
| **组织方式** | 按功能/领域组织（不是按类型：controller/service/dao） |
| **提取工具类** | 重复代码超过 3 次必须提取 |

```
❌ 按类型组织（传统 Java 风格）：
src/
├── controller/      # 所有 controller
├── service/         # 所有 service
├── dao/             # 所有 dao
└── model/           # 所有 model

✅ 按领域组织（DDD 风格）：
src/
├── user/            # 模块自包含
├── order/
└── payment/
```

## 三、命名规范（通用）

| 元素 | 强类型编译型 | 动态/解释型 | 前端 | 数据库 |
|------|------------|------------|------|--------|
| **类/类型** | PascalCase | PascalCase | PascalCase | - |
| **函数/方法** | camelCase | snake_case (Python) / camelCase (JS) | camelCase | - |
| **变量** | camelCase | snake_case (Python) / camelCase (JS) | camelCase | - |
| **常量** | UPPER_SNAKE | UPPER_SNAKE | UPPER_SNAKE | - |
| **包/命名空间** | lowercase | lowercase | kebab-case | - |
| **文件名** | 与类同名 | snake_case | PascalCase (组件) / kebab-case | snake_case |
| **表名** | - | - | - | 复数 snake_case |
| **字段名** | - | - | - | snake_case |

**通用禁词**：
- ❌ 缩写晦涩：`mgr` `util` `handler`（除非项目约定）
- ❌ 单字母变量：`a` `b` `x`（循环索引除外）
- ❌ 类型前缀：`strName` `iCount`（现代语言不需要）
- ✅ 业务语义：`customerName` `activeOrderCount`

## 四、错误处理（通用）

| 层 | 错误处理方式 |
|----|------------|
| **用户界面** | 友好错误提示（不暴露内部细节） |
| **API 层** | 标准化错误响应（HTTP code + message + trace_id） |
| **业务逻辑** | 抛自定义异常 / Result<T, E>；附上下文 |
| **数据访问** | 详细日志 + 重试 + 上抛 |
| **基础设施** | 监控告警 + 自动恢复 |

**禁止**：
- ❌ 静默吞掉错误（`catch {}` / `except: pass`）
- ❌ 用 `null` / `None` 代替错误信号
- ❌ 把异常字符串硬编码到 UI
- ❌ 在循环中重复抛同一个异常（应收集后聚合抛）

## 五、输入验证（通用）

| 原则 | 说明 |
|------|------|
| **系统边界必验证** | API 入口 / CLI 参数 / 文件读取 / 第三方响应 |
| **基于 schema 验证** | JSON Schema / TypeScript 类型 / Pydantic / Bean Validation |
| **快速失败** | 错误立即抛出，不带病运行 |
| **清晰错误消息** | 指明哪个字段、什么值、为什么错 |
| **不信任外部数据** | API 响应、用户输入、文件内容一律验证 |

```python
# Python + Pydantic
class CreateUserRequest(BaseModel):
    name: str = Field(..., min_length=1, max_length=50)
    age: int = Field(..., ge=0, le=150)
    email: str = Field(..., regex=r"^[\w.+-]+@[\w-]+\.[\w.-]+$")
```

## 六、测试规范（通用）

### 6.1 FIRST 原则
Fast（快）/ Independent（独立）/ Repeatable（可重复）/ Self-validating（自验证）/ Timely（及时）

### 6.2 AAA 模式
Arrange（准备）/ Act（执行）/ Assert（断言）

### 6.3 测试名描述行为
不要 `test1` `testMethod`，要 `should_return_error_when_user_not_found`

## 七、版本控制（Git）

### 7.1 提交消息格式（Conventional Commits）

```
<类型>(<范围>): <描述>

<可选正文>

<可选页脚>
```

| 类型 | 用途 |
|------|------|
| `feat` / `fix` / `refactor` / `docs` / `test` / `chore` / `perf` / `ci` / `style` | 见名知义 |

### 7.2 分支策略

推荐 GitHub Flow（持续部署）或 Git Flow 简化版，详见各语言规范。

## 八、安全规范（通用底线）

| 类别 | 规范 |
|------|------|
| **敏感信息** | 不入库；用环境变量/密钥管理 |
| **SQL 注入** | 参数化查询；禁止字符串拼接 |
| **XSS** | 输出转义；CSP 头 |
| **CSRF** | Token 验证；SameSite cookie |
| **认证** | 不自己实现；用成熟库 |
| **密码** | bcrypt/argon2；不存明文 |
| **依赖** | 定期更新；漏洞扫描 |
| **HTTPS** | 全站 HTTPS；HSTS 头 |

## 九、可观测性（默认要求）

| 维度 | 要求 |
|------|------|
| **日志** | 结构化（JSON）；含 trace_id；分级 |
| **指标** | QPS / 延迟 / 错误率 |
| **链路追踪** | OpenTelemetry |
| **告警** | 错误率 > 1% 告警；P99 延迟 > 阈值告警 |

## 十、质量检查清单（每次 PR 必查）

- [ ] 代码可读且命名良好
- [ ] 函数 < 50 行（必要时提取）
- [ ] 文件 < 800 行（必要时拆分）
- [ ] 嵌套不超过 4 层
- [ ] 错误处理完整（无静默吞错）
- [ ] 无硬编码值（用常量或配置）
- [ ] 系统边界有输入验证
- [ ] 测试覆盖率达标（按语言，§二-§八）
- [ ] 无敏感信息入库
- [ ] CI 通过

# 第二部分：按语言类型分发规范

## 十一、语言类型总览

| 类型 | 典型语言 | 默认规范要点 | 测试覆盖率门槛 |
|------|---------|------------|--------------|
| **强类型编译型** | Java / Go / Rust / Kotlin / C++ / C# / Swift | 严格类型 + 编译期检查；空安全；接口冻结 | ≥80% |
| **动态解释型** | Python / JavaScript / Ruby / PHP / Lua | 类型注解 + Linter + 测试 | ≥80% |
| **脚本型** | Bash / PowerShell / Makefile / Batch | 安全第一（参数校验/路径白名单） | ≥60%（集成测试） |
| **前端框架** | Vue / React / Svelte / 微信小程序 | 组件复用 + 状态管理 + 浏览器兼容 | ≥70%（组件测试） |
| **移动端** | iOS Swift / Android Kotlin / Flutter / React Native | 平台规范 + 真机测试 | ≥70% |
| **数据/ML** | SQL / Python(PyTorch/TF) / R | 数据库规范 + 模型可复现 | 关键路径 100% |
| **混合栈** | 前后端 + 移动端 | 双技能加载 + 跨边界契约 | 各语言门槛取最高 |

## 十二、强类型编译型（Java / Go / Rust / Kotlin / C++ / C# / Swift）

### 12.1 通用规范

| 维度 | 规范 |
|------|------|
| **命名** | 驼峰/蛇形按语言约定；常量全大写下划线；类型/接口大写开头 |
| **类型** | 严格禁止隐式类型转换；nullable 类型显式标注；接口优于类继承 |
| **错误处理** | 不静默吞错；显式 error / Exception 向上抛；关键路径日志带上下文 |
| **并发** | 共享状态加锁或无状态化；避免全局可变 |
| **资源管理** | 自动释放（defer / RAII / using）；文件/连接必须关闭 |

### 12.2 各语言要点

**Java（17+）**
- `record` 替代简单 DTO；`sealed class` 控制继承
- Stream API 优先，避免超过 3 层嵌套
- 依赖注入优先构造器注入
- 测试：JUnit 5 + Mockito + AssertJ；覆盖率 JaCoCo

**Go（1.21+）**
- `gofmt` / `goimports` 强制；`go vet` / `staticcheck` 通过
- `errors.Is` / `errors.As` 断言；自定义错误实现 `Error() string`
- 并发：channel 优先；`context.Context` 贯穿调用链
- 测试：标准库 `testing` + `testify`；表驱动测试

**Rust（2021 edition+）**
- `cargo fmt` / `cargo clippy` 强制；`unsafe` 必须有注释
- 错误用 `Result<T, E>`；`panic!` 仅用于不可恢复错误
- 测试：标准 `#[test]` + `proptest`（属性测试）

**Kotlin（1.9+）**
- 空安全 `String?` / `String` 严格区分
- 协程：`CoroutineScope` / `launch` / `async` / `Flow`
- 测试：JUnit 5 + Kotest + MockK

**C++（C++17/20）**
- RAII 强制；智能指针；禁止裸 `new` / `delete`
- 测试：GoogleTest + gcov/lcov

**C#（.NET 8+）**
- nullable reference types 启用；`record` / `record struct`
- 测试：xUnit + NSubstitute + FluentAssertions

**Swift（5.9+）**
- SwiftUI 优先 UIKit（旧项目保留）；`async/await` 替代回调
- `@MainActor` 标注 UI 相关
- 测试：XCTest + Quick/Nimble

## 十三、动态解释型（Python / JavaScript / Ruby / PHP / Lua）

| 维度 | 规范 |
|------|------|
| **类型** | 启用类型注解（Python typing / TypeScript / Ruby Sorbet） |
| **风格** | Linter 强制（pylint / eslint / rubocop） |
| **依赖** | requirements.txt + lock 文件（pip-tools / npm ci / bundler） |
| **并发** | 异步优先（asyncio / Promise / Fiber） |

**Python（3.11+）**
- `from typing import ...`；复杂结构用 `TypedDict` / `dataclass` / `Pydantic`
- Linter: ruff（替代 flake8+isort+black）；格式化 ruff format
- 包管理：uv / poetry；lock 文件入库
- 测试：pytest + pytest-cov + hypothesis

**JavaScript / TypeScript**
- TypeScript strict 模式；`any` 禁止（除非明确边界）
- ESLint + Prettier 强制；ESM 模块优先
- 测试：Vitest/Jest + Testing Library

**Ruby（3.2+）**
- 风格：rubocop 强制；类型：Sorbet / RBS
- 测试：RSpec + SimpleCov

**PHP（8.2+）**
- `declare(strict_types=1);`
- 测试：PHPUnit + Pest

## 十四、脚本型（Bash / PowerShell / Makefile / Batch）

**安全第一**

| 维度 | 规范 |
|------|------|
| **入口** | `set -euo pipefail`（Bash）；`$ErrorActionPreference = "Stop"`（PowerShell） |
| **参数校验** | 必填参数缺失即报错退出 |
| **路径** | 禁止 `rm -rf $UNCHECKED_VAR`；路径白名单或相对项目根 |
| **错误处理** | trap + EXIT handler 清理临时文件 |
| **可移植性** | 避免 Bash 专属语法；跨平台用 shebang 标注 |

**Bash（4.0+）**
- `shellcheck` 通过；长脚本拆函数
- 引号：变量必须双引号包裹；避免 word splitting
- 测试：bats-core

**PowerShell（7+）**
- 跨平台用 PowerShell Core（`pwsh`）
- 风格：PSScriptAnalyzer 通过

## 十五、前端框架（Vue / React / Svelte / 微信小程序）

| 维度 | 规范 |
|------|------|
| **组件** | 单一职责；props 强类型（TS）；事件向上抛 |
| **状态管理** | 小应用：组件 state；中应用：Pinia/Zustand；跨页：URL/query |
| **样式** | scoped CSS / CSS Modules / Tailwind；禁止全局污染 |
| **路由** | 路由懒加载；权限路由 meta 声明 |
| **可访问性** | a11y 基础：aria-label、语义化标签、键盘可达 |

**Vue 3**
- Composition API + `<script setup lang="ts">`
- 测试：Vitest + Vue Test Utils

**React 18+**
- 函数组件 + Hooks；禁止 class component
- 状态：服务器状态 React Query；客户端状态 Zustand
- 测试：Vitest + RTL + MSW

**Svelte / SvelteKit**
- `.svelte` 单文件组件；stores 跨组件共享

**微信小程序**
- 双线程模型（逻辑层/渲染层）；setData 最小化
- 组件化：自定义组件 + behaviors

## 十六、移动端（iOS / Android / Flutter / React Native）

**iOS（Swift / SwiftUI）**
- SwiftUI 优先；UIKit 旧项目保留
- 内存：避免循环引用；weak / unowned 标注
- 性能：Instruments 检测；启动时间 < 400ms

**Android（Kotlin / Jetpack Compose）**
- Jetpack Compose 优先；XML 旧项目保留
- 协程全链路；Room 数据库；Hilt 注入
- 性能：LeakCanary + Macrobenchmark

**Flutter（Dart）**
- null safety 启用；Riverpod / Bloc 状态管理
- 测试：flutter test + integration_test

**React Native**
- TypeScript 强制；Hermes 引擎
- 导航：React Navigation；状态：Zustand
- 原生模块：Turbo Modules（新项目）

## 十七、数据/ML（SQL / Python 数据栈 / R）

### 17.1 SQL（跨方言通用）
- **关键字大写**：`SELECT` / `FROM` / `WHERE`；表/字段小写蛇形
- **命名**：表名复数；主键 `id`；外键 `<ref_table>_id`；时间字段 `_at` / `_date`
- **索引**：高频查询列；外键；时间字段
- **NULL**：明确 `IS NULL` / `IS NOT NULL`
- **事务**：DML 必须显式事务；大事务拆小
- **可移植性**：避免方言专属语法；CTE 优先于子查询

### 17.2 Python 数据栈
- numpy / pandas 优先；避免 Python 循环处理大数据
- 模型可复现：random seed；超参记录（MLflow / W&B）
- 数据版本化：DVC / Delta Lake

## 十八、混合栈

当项目涉及多种语言/栈时：

1. **明确边界**：每个模块的栈边界清楚，跨边界通过 HTTP / gRPC / Message Queue
2. **接口契约**：跨语言接口用 OpenAPI / Protobuf / GraphQL 定义；前后端共享类型生成
3. **双技能加载**：编码 Agent 同时加载多个语言的 cross-language 子规范
4. **统一测试**：跨边界用契约测试（Pact / WireMock）
5. **覆盖率取最高**：各栈的测试门槛取最高（如：后端 ≥80% + 前端 ≥70% → 取 80%）
