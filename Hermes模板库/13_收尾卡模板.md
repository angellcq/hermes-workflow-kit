# 收尾卡模板（v5.0 新增）
> **模板编号**: 13 ｜ **环节**: 交付收尾（S7，对应阶段码 `CLS`） ｜ **填写人**: Hermes
> **定位**: 收尾卡是**交付闭环卡**——文档归档、追踪矩阵闭合、看板归零、复盘留痕。它不产出代码。
> **命名**: `任务卡_<模块>-CLS-<序号>_<短标题>.md`；assignee `hm-delivery`
> **为什么单独建卡**: 收尾工作量大且易漏（文档未入库/矩阵未回填/板未归档），挂在开发卡尾巴上必然被跳过

# 收尾卡:【T-<模块>-CLS-<序号>】

## 一、基本信息

| 字段 | 内容 |
|------|------|
| 任务 ID | 【`T-<模块>-CLS-<n>`】 |
| 阶段 | 交付收尾 |
| assignee | `hm-delivery` |
| 负责人（派生） | Hermes |
| 依赖任务 | 【验收卡 `T-<模块>-QA-<n>`；`link` 落板】 |
| 交付范围 | 【本迭代涉及的卡 ID 全集 + 文档清单】 |
| 看板卡 ID | 【t_xxxxxxxx】 |
| 当前状态（卡面三态） | 【待执行 / 正在运行 / 已完成】 |

## 二、收尾清单（逐条打勾，缺一条不得 complete）

### 2.1 文档归档

- [ ] PRD / HLD / DD 已入库（`git log --oneline -- <文件>` 可查到提交，不只看工作区）
- [ ] 交付验证报告（模板 07）已入库，8 项验证清单齐备
- [ ] 移交文档（模板 09）已写：接手人只读它就能继续
- [ ] 版本记录（模板 10）已回填；`CHANGELOG.md` 有本迭代条目
- [ ] 文中残留的 `【】` 占位符与 `> 💡` 填写指引已清零

### 2.2 追踪矩阵闭合

- [ ] 每条 PRD 需求 → 至少一张 DONE 卡 → 至少一个通过的验证项
- [ ] 未覆盖需求已显式登记为「本期不做」并附理由（不许静默丢弃）
- [ ] 偏差项（执行中偏离 DD 的地方）已记录影响面与处置

### 2.3 代码与分支

- [ ] 产出已合入基线（`git merge-base --is-ancestor <lane-sha> <base>` 为真，或逐文件比对确认等价）
- [ ] 临时 worktree / 分支已清理；`.worktrees/` 无残留（`git worktree list` 只有主检出）
- [ ] 未推送提交已向用户报备（push 由用户发话，助手不自行推送）

### 2.4 看板归零

- [ ] 本迭代全部卡 `done` 并 `archive`（板面活跃卡归零）
- [ ] `blocked` 卡逐张处置：修 / 转下期 / 显式废弃，不许留悬空
- [ ] 本卡 `comment` 写收尾摘要 → `archive`

## 三、复盘（必填，≥3 条）

| # | 类别 | 内容 |
|---|------|------|
| 1 | 做对了什么（可复用） | 【具体做法 + 为什么有效】 |
| 2 | 踩了什么坑（可预防） | 【现象 → 根因 → 下次怎么防】 |
| 3 | 流程/资产改进项 | 【要改哪个模板/脚本/制度条款；不改的写明理由】 |

> 复盘条目若指向工作流资产缺陷，**当场建改进卡**（哪怕本期不做），否则下次必然复发。

## 四、交付结论

| 项 | 内容 |
|---|---|
| 需求覆盖 | 【N/N 条 PRD 需求已闭环】 |
| 交付物 | 【文档清单 + 代码提交范围】 |
| 遗留项 | 【明确列出 + 归口人 + 计划卡 ID；无则写"无"】 |
| 结论 | 【可交付 / 有条件交付（列条件）/ 不可交付（列阻塞）】 |
| 收尾人 + 时间 | 【Hermes，YYYY-MM-DD HH:mm】 |
