> ⚠️ 本机有两个 Hermes home，先确认部署目标：
> - **CLI/网关实例** home = `C:\Users\luchunqing\.hermes\`
> - **桌面版（Hermes Studio）** home = `C:\Users\luchunqing\AppData\Local\hermes\`
> 两个实例的 SOUL.md 互不相通，要在哪个实例生效就部署到哪个目录（或都部署）。

1. **备份现有人格**（务必先做）：
   ```bash
   cp ~/.hermes/SOUL.md ~/.hermes/SOUL.md.bak.20260904
   cp ~/.hermes/AGENTS.md ~/.hermes/AGENTS.md.bak.20260904
   ```
2. **复制三个产物**到目标 home（主人格/制度层部署时重命名为 SOUL.md / AGENTS.md）：
   ```bash
   cp "F:/千问工作/合并后版本/Hermes_主人格.md" ~/.hermes/SOUL.md
   cp "F:/千问工作/合并后版本/Hermes_制度层.md" ~/.hermes/AGENTS.md
   cp -r "F:/千问工作/合并后版本/Hermes模板库" ~/.hermes/Hermes模板库
   ```
   （部署桌面版则把 `~/.hermes` 换成 `$LOCALAPPDATA/hermes`；SOUL.md/AGENTS.md 是受保护文件名，复制时如被拦截请手动确认授权）
3. **若部署到其他 home**：同步修改 SOUL.md 资产路由表中的路径。
4. **重启 Hermes 进程**（桌面端/网关/CLI 退出重开）使新人格生效。
5. **验证**：新会话问一句"你是谁、你的工作流是什么"，应回答技术项目管家身份并能按需读出模板。

> 回滚：把 `.bak.20260904` 备份拷回原名即可。

## 五、怎么使用

### 5.1 分级适用（人格内置判断）

| 级别 | 场景 | 行为 |
|------|------|------|
| **Tier 0 快任务** | 查询、改一行配置、修单点 bug、跑脚本、写一段 SQL | 直接执行，不走流程；完成后给结果+证据 |
| **Tier 1 中型任务** | 单模块功能、明确的小需求 | 裁剪流程：澄清(≤1轮) → 任务卡 → 执行 → 验证，跳过 HLD/LLD 全套 |
| **Tier 2 完整交付** | 多模块、多任务、需求模糊、合规项目 | 完整七阶段：S1 澄清 → S2 PRD → S3 HLD/DD → S4 拆解派发 → S5 跟踪 → S6 验证 → S7 归档 |

用户也可以在指令中显式指定："走全流程做 X" / "这个直接改，别走流程"。

### 5.2 一个 Tier 2 完整交付的典型流程

1. 用户给模糊需求 → Hermes 列歧义清单一次性澄清（≤2 轮）
2. 读模板 01 → 产出 `PRD_xxx_v1.0.md`（含追踪矩阵骨架）
3. 读模板 02/03 → 产出 HLD、DD（每模块），设计条目逐条回溯 US 编号
4. 读模板 04 → 拆任务卡（单卡 ≤4h、DAG 依赖、files_scope 不重叠）
5. 派发：独立任务并行（`delegate_task` 或 Claude Code `claude -p`），同文件串行
6. 检查点核对（派发确认/里程碑/用户询问时），三态汇报
7. 每卡完成读模板 07 做 7 项验证 + 追踪矩阵闭环核对
8. 全部通过后看板归档，交付物清单齐套

### 5.3 编码委派（Claude Code）

- **单任务一律 Print 模式**：`claude -p "任务" --allowedTools "Read,Edit,Write,Bash" --max-turns N`（必设 max-turns）
- **多轮迭代用 Hermes pty 后台**：`terminal(background=true, pty=true)` 起 claude，`process(submit)` 输入，`read_terminal`/`process log` 监控（**不是 tmux，本机没有**）
- 委派指令用模板 04 第四节"派发通知"
- 项目红线（如建投 MDF 规范）随每次派发指令附带

### 5.4 注意事项

- 模板铁律不变：先读后写、按节填写、`【】` 占位符清零、`>💡` 指引定稿删除
- 协商触发：歧义/冲突/复杂度命中即开会（L2+），L3 不可逆操作必须用户终审
- 看板状态以 `hermes kanban` 内置看板为事实源，聊天口头进度须核实后落板
